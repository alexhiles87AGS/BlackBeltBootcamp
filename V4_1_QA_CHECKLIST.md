# V4.1 QA Checklist

Test at 390×844 and 375×667, then on a physical iPhone/Safari before publishing.

## Home
- [ ] Greeting is compact.
- [ ] Today/next workout and weekly progress appear near the top without layout overflow.
- [ ] Start/Resume opens the correct session.

## Workout mode
- [ ] Only the current exercise is expanded.
- [ ] Exercise queue changes current exercise.
- [ ] Previous performance is shown when history exists.
- [ ] Reps opens numeric keyboard and weight allows decimals on iPhone.
- [ ] Complete Set gives immediate saved feedback and starts the rest timer.
- [ ] Complete without numbers works.
- [ ] Next exercise works.
- [ ] Finish workout returns to Dashboard and session remains completed after Sync/refresh.
- [ ] Lock/unlock or background/foreground during a workout does not lose current logging state unexpectedly.

## Exercise demo / Library
- [ ] Demo modal fits entirely inside the iPhone viewport and Close is visible.
- [ ] Library rows are compact.
- [ ] Body part + muscle filtering works together.
- [ ] Favourite toggle works.
- [ ] Recent list updates after opening an exercise.
- [ ] Duplicate names show a useful variant/equipment label.

## Nutrition
- [ ] Summary is first.
- [ ] Add meal and water shortcuts are prominent.
- [ ] Empty day says Nothing logged yet.
- [ ] Recent meal shortcut prefills correctly.
- [ ] Edit targets opens/closes and saves.

## Progress
- [ ] Latest weight/date show even with one measurement.
- [ ] Trend guidance is shown until at least two relevant measurements exist.
- [ ] Weighted-lift empty state is consolidated.
- [ ] 1RM / PR / volume content appears when logs exist.

## Navigation / accessibility
- [ ] Hamburger is the only secondary menu entry point.
- [ ] Bottom navigation has Home, Training, Nutrition and Progress.
- [ ] Previous/next week controls work.
- [ ] Key touch controls are comfortable on iPhone.
- [ ] Test Safari with larger text and keyboard open.
